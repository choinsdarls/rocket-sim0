# 开源｜从零手搓一个火箭发射仿真系统：单文件 HTML、零依赖、断网也能跑

> **摘要**：这是一个纯前端的火箭发射弹道仿真系统。从发射场点火、程序转弯、级间分离，到入轨判定与残骸落区预测，全部在浏览器里离线完成数值积分。没有后端、没有 npm install、不发起任何网络请求——把 HTML 存到 U 盘，插到任何一台有浏览器的电脑上双击就能跑。项目已开源，本文讲清楚它做了什么、怎么做的、以及踩了哪些坑。

## 二、为什么要自己写一个

想认真搞懂一枚火箭从点火到入轨到底经历了什么，光看公式是不够的，得能"拧旋钮看变化"。

查了一圈，市面上的选择有点尴尬：

- **专业工具**（STK、GMAT）：建模能力强，但安装配置劝退，想当场给同事演示一下"改发射方位角会怎样"很不方便；
- **在线演示/教学动画**：好看是好看，但基本是预渲染的动画，参数改不动，看不到物理过程；
- **自己写脚本**：能跑，但做完是一堆散装文件，换个电脑还得配环境。

于是定下了三个硬约束，所有设计都围绕它们展开：

| 约束 | 含义 |
|---|---|
| **零依赖、断网可用** | 不引 CDN、不请求瓦片。MapLibre 引擎与世界矢量底图全量内嵌 |
| **单文件交付** | 源码分片开发，构建合并为一个 HTML，双击即用 |
| **真解算** | 每次点解算都做完整数值积分，不是播预渲染动画 |

最终产物约 **1.25 MB**（其中 MapLibre 引擎与样式内嵌占 0.96 MB），打开即用。

## 三、它能干什么

### 3.1 建模对象

- **5 种运载火箭**：长征五号、长征七号、长征二号 F、Falcon 9 Block 5、Electron

### 3.2 一次解算能看到什么

| 输出 | 说明 |

| 地面轨迹 + 星下点 | 画在内嵌矢量地图上，7 种底图可切（含离线矢量） |
| 飞行阶段条 | 一级动力段 / 级间分离 / 二级动力段 / 无动力滑行 / 入轨，分色显示 |
| 弹道剖面 | 高度-地面航程曲线，播放时随进度推进 |
| 遥测曲线 | 速度 / 高度 / 动压 / 过载四条同图，与剖面并列 |
| 实时读数 | 高度、速度、动压 Q、过载、总质量、马赫数、MET 任务时间 |
| 飞行事件序列 | 点火、抛罩、级间分离、关机、入轨……按 MET 时间轴逐条记录 |
| 入轨结果 | 分「已入轨 / 转移轨道（需 Δv 圆化）/ 未入轨」三态，转移轨道直接给出圆化所需 Δv |
| 残骸落区 | 整流罩与各分离级各自的落点预测，在轨残骸自动过滤 |

### 3.3 交互与导出

- 时间轴 **0.25× ~ 8×** 变速回放，可拖动定位任意时刻
- 三窗口双击放大 + 拖动 + 双击还原
- **方案存取**：localStorage 自动记忆上次参数，也可导出 JSON 跨设备复用
- **自定义火箭与发射场**：按 schema 写 JSON 导入，不用改一行源码
- **四种导出**：CSV（带 BOM，Excel 直接开）、GeoJSON、KML（Google Earth）、GeoLibre 工程图层
- 快捷键：`Space` 播放/暂停、`←/→` 步进、`?` 帮助

## 四、技术内核：物理建模

这是整个项目最花功夫的部分，也是它区别于"动画演示"的根本。物理内核是**纯函数、零 DOM 依赖**，可以直接在 Node 或 Web Worker 里跑。

数据流向：

```
ECI 惯性系 RK4 积分  →  ECEF 地固系投影  →  WGS84 经纬高 / 轨道根数 / 残骸落区
```

### 4.1 坐标系

WGS84 椭球，长半轴 6378137.0 m、短半轴 6356752.314245 m，第一偏心率平方 6.69437999014e-3。

积分在 **ECI 惯性系**进行（避免科里奥利项），每步投影到 ECEF 得到地理坐标：

```javascript
/** ECI → ECEF：绕 Z 轴反向旋转地球自转角 θ = Ω·t */
function eci2ecef(r, theta){
  const c = Math.cos(theta), s = Math.sin(theta);
  return [ c*r[0] + s*r[1],
          -s*r[0] + c*r[1],
           r[2] ];
}
```

地理坐标 ↔ ECEF 用迭代法反解纬度（椭球方程没有闭式解）。这条链路的往返误差实测 **< 1 mm**，是可验证的指标之一。

### 4.2 积分器与受力

四阶 Runge-Kutta，步长默认 0.2 s，滑行段放大 6 倍提速。核心是导数函数：

```javascript
function deriv(t, r, v, alt, thrustVec){
  const g = gravity(r);                                   // 点质量 + J2
  const atm = atmosphere(alt);                            // US76
  const vRel = v3.sub(v, v3.cross([0,0,C.OM], r));        // 扣掉地球自转牵连速度
  const vr = v3.len(vRel);
  const M = vr / atm.a;                                   // 马赫数
  const D = 0.5 * atm.rho * vr * vr * dragCoef(M) * currentArea();
  const dragF = vr > 1e-6 ? v3.mul(vRel, -D / vr) : [0,0,0];
  // 阻力是力，必须除以质量才得到加速度
  const a = v3.add(g, v3.mul(v3.add(dragF, thrustVec), 1/m));
  return { dr: v, dv: a, D, M, q: 0.5*atm.rho*vr*vr, atm, thrustAcc: v3.len(thrustVec)/m };
}
```

几个关键点：

- **重力**用点质量 + **J2 二阶带谐项**，不是简单的 `g=9.8`：

```javascript
// a_J2 = 1.5·J2·(μ/R²)(Re/R)² · (r/R)·(5·(z/R)² − {1,1,3})
const k = 1.5 * C.J2 * C.MU * C.RE * C.RE / Math.pow(R, 4);
```

- **大气**用 US Standard Atmosphere 1976，位势高度换算，0–84.852 km 共 8 层分层，每层给温度递减率与基准气压：

```javascript
const ATM = [
  [0,      -0.0065, 288.15,  101325.0],
  [11000,   0.0,    216.65,  22632.06],
  [20000,   0.001,  216.65,  5474.889],
  [32000,   0.0028, 228.65,  868.0187],
  [47000,   0.0,    270.65,  110.9063],
  [51000,  -0.0028, 270.65,  66.93887],
  [71000,  -0.002,  214.65,  3.956420],
  [84852,   0.0,    186.946, 0.373400]
];
```

- **阻力必须除以质量**——我一开始就在这里踩过坑，把阻力当加速度直接加进去了，结果小火箭 Electron 和大火箭 CZ-5 的弹道形状差不多，明显不对。

### 4.3 推进与质量流

多级构型用声明式配置，支持并联点火（助推器）与串联点火（上级）：

```javascript
cz5: {
  key:'cz5', name:'长征五号 (CZ-5)', nation:'中国',
  area: 52.0, fairing: 4200, fairingAlt: 115000, payload: 22000, leo: 25000,
  stages:[
    // tIgn:0 → 与首发级并联点火；after:i → 第 i 级关机分离后 delay 秒点火
    {name:'助推器 ×4', tIgn:0, prop:564000, dry:48000, tvac:10720000, tsl:9600000, ivac:335, isl:300, area:52.0},
    {name:'芯一级',    tIgn:0, prop:104000, dry:20000, tvac:1400000,  tsl:1020000, ivac:430, isl:312, area:20.0},
    {name:'二级',      after:1, delay:3, prop:27000, dry:12000, tvac:183000, tsl:120000, ivac:442, isl:300, area:20.0}
  ]
}
```

海平面/真空双套推力与比冲，按高度插值。质量随推进剂消耗递减，级间抛离干重，整流罩到达指定高度自动抛掉——**迎风面积也随之收缩**（完整构型的迎风面积约是洁净末级的 3 倍），这个细节直接影响上升段阻力。

### 4.4 制导律

程序转弯（pitch program）参数化：起始时刻 `kick`、结束仰角 `pitchEnd`、转弯指数 `expo`、攻角上限 `aoaMax`，再加一个二级俯仰偏置 `bias2`。

关机判据是"能量 + 近地点"双达标，目标近地点取：

```javascript
periTarget = clamp(tAlt * 0.38, 130000, 200000)
```

即瞄准目标高度的 38%（夹在 130–200 km），让末级关机后自然滑行到目标高度——这是标准的"低近地点转移轨道再圆化"思路，也解释了为什么结果面板要区分"已入轨"和"转移轨道"。

上手最简单的路径是点「自动配平入轨」，它会连续迭代 17 次自动搜索可行参数组合。

### 4.5 残骸落区预测

每个分离体（整流罩、已分离级）在分离时刻记录状态矢量，然后**各自**做纯弹道积分至地表。

这里有个容易出错的地方：如果不做区分，长期在轨或延迟再入的残骸会因为"积分超时返回末位置"而被画成一个虚假落点。所以判据要分三路：

```javascript
// 积分超时分支：按比机械能 / 椭球根数判定是否实际在轨
orbital  = (el.a > 0) && (el.e < 1) && (el.peri > 120000);
timedout = true;
// 触地分支：orbital = false, timedout = false
```

只有 `ok && !orbital` 的才画成落点。这条后来专门加了回归测试锁住。

## 五、DIMS：残骸溅落测量子系统

这是项目里最重的一块（76 KB），规格来自航天靶场的实际测量需求。

**核心设计判断：按残骸件分组解算。** 不同分离体的落点可以相距上千公里，把它们混在一起做统计在物理上根本不成立，必须各自成区。

处理流程：

```
蒙特卡洛散布采样（600 条/件）
   ↓
高斯核密度场（88×88 网格）
   ↓
Marching Squares 提取等值线（50% / 90% / 99%）
   ↓
凸包外包络 + 协方差置信椭圆（CEP50 / R90 / R95）
   ↓
散点 / 热力图 / 下程-横偏散布 三种视图
   ↓
CSV / JSON / GeoJSON / KML / GeoLibre 导出
```

数据校验做了五道：量纲范围检查、MAD 稳健离群剔除、马氏距离（χ² 2 自由度 99% 门限）、重复采样检测、坐标往返精度自检。

性能上，批量采样用 `setTimeout(0)` 分片推进，每帧只占 14 ms 预算，600 条采样也不会卡住 UI。指标：交互响应 < 500 ms，三维测量 RMS ≤ 0.5 m（ECEF 米级双精度主存储）。

## 六、工程实现：单文件是怎么来的

1.3 MB 的 HTML 直接改是灾难。所以源码按职责切成 5 个分片，`build.py` 负责合并：

```
build/
├── part1_head.html     样式与 CSS 变量（主题系统）
├── part2_body.html     页面结构与 DOM
├── part3_physics.js    ★ 物理内核（纯函数，支持 module.exports）
├── part4_map.js        地图控制：底图降级、图层安装、飞行更新
├── part5_ui.js         状态机、解算中枢、图表绘制、交互
├── world_data.js       Natural Earth 110m 矢量（陆地/国界/城市）
├── build.py            分片合并 + 构建护栏
└── dims/
    ├── dims.js         DIMS 子系统
    ├── dims.css
    ├── patch.py        12 锚点幂等注入器
    └── base.html       注入基线（= build.py 输出快照）
```

DIMS 是大型子系统，通过 `patch.py` 以 **12 个锚点**注入到 `build.py` 的产物上，而不是写进分片——这样 DIMS 可以独立演进，且 `patch.py` 始终从 `base.html` 快照重建再注入，可反复重跑不出错。

**构建护栏**（单文件项目最容易静默坏掉，所以必须有）：

- 合并前对每个 JS 分片跑 `node --check`，语法错误直接中断
- 注入 `BUILD_VERSION` 与日期戳到 `window.__BUILD__`
- 记录体积基线，偏离 > 10% 自动预警

```bash
npm install       # 仅冒烟测试需要 jsdom，构建本身零依赖
npm run build     # 合并分片 → 火箭发射仿真系统.html
npm test          # 物理内核回归（13 项，纯 Node）
npm run test:dom  # jsdom 冒烟（59 项）
npm run verify    # build + test 一条龙
```

## 八、踩过的坑

这部分我觉得比功能清单更有价值，都是真实调试记录。

### 坑 1：画布高度指数增长

用户反馈"点解算后地图和图表大小被改变、内容时有时无"。根因在 dpr 处理：

```javascript
// 错误写法：height 属性被覆写成物理像素后，下一帧再乘一次 dpr
h = parseInt(cv.getAttribute('height'));
cv.height = h * dpr;        // 150 → 300 → 600 → …每帧翻
```

dpr=1 的环境完全不会触发，所以之前的 headless 验证一直没发现，只在 dpr=2 的机器上爆炸。修法是逻辑高度只读一次存进 `cv.dataset.plotH`，位图尺寸仅在真正变化时重设。

**教训**：高分屏相关的 bug，必须在测试环境里显式模拟 dpr=2。

### 坑 2：`attribution: undefined` 导致底图切不动

用户反馈"卫星图切不了"。查下来是 MapLibre 的样式校验——在非首层栅格图层上写了 `attribution: undefined`，校验要求这个字段必须是字符串，**整个 `setStyle` 直接被拒绝**，底图保持原样。

只有两层栅格图的底图（Esri 影像/灰底）中招，单层的不受影响，所以现象是"有的能切有的不能"。

### 坑 3：`overflow` 让 flex 子项被压缩到 0

用户说"展开入轨结果后，残骸溅落测量面板消失了"。根因是 CSS 规范里的一条：带 `overflow`（非 `visible`）的 flex 子项，其自动最小尺寸为 0。右栏内容超高时，flex 算法就把最"可压缩"的那个面板缩到了 ~0 高。

修法是给它 `flex:0 0 auto`，并给右栏所有面板加 `flex-shrink:0`。

### 坑 4：死分支让正确性修复失效

`predictImpact()` 从不返回 `orbital` 字段，但地图渲染和工程导出里都写了 `if (im.orbital) return;`。结果这行过滤**从来没生效过**——在轨残骸和超窗亚轨道体一律被画成落点。

这种"代码看起来在防御，实际上永远不触发"的死分支，是最隐蔽的一类 bug。修完后专门补了回归测试锁住。

### 坑 5：重复 DOM id

`part2_body.html` 里有两个 `id="cityLabels"` 的 div，`getElementById` 只取第一个，第二个是死节点。同时 CSS 里有两块完全重复的样式。这种问题在单文件项目里靠肉眼很难发现，后来是靠脚本扫出来的。

## 九、已知边界

说清楚不做什么，比吹能做什么重要：

- **二维弹道平面内建模**：不做六自由度姿态动力学、不做结构弹性与推进剂晃动
- **不回收构型**：Falcon 9 按一级不回收（全额运力）计算
- **无轨道递推**：只算到入轨关机时刻，不做多圈递推与轨道衰减
- **静态标准大气**：不含风场与实时空间天气
- **制导律内建**：暂未开放自定义制导回调接口
- **解算跑在主线程**：长时间解算会短暂冻结 UI，计划移入 Web Worker

## 写在最后

这个项目最花时间的不是 UI，而是物理建模的"较真"：大气分层边界连不连续、坐标往返误差多少毫米、在轨残骸会不会被误画成落点。这些细节不写进功能清单，但它们决定了这个东西到底是"能看的动画"还是"能用的工具"。

如果你也是航天/仿真爱好者，欢迎：

- 补充火箭构型与发射场数据（按 `VEHICLES` / `SITES` 的 schema 提交即可）
- 审查物理模型的正确性（尤其是制导律经验常数与关机判据）
- 帮忙推进 Worker 化与模块解耦
